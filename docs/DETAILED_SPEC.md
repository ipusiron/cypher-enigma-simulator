# Cypher Enigma Simulator 詳細仕様書

## 1. 目的と位置づけ

本ツールは、Cypher系パズルで使用されるエニグマ風暗号機を再現・検証するための
**教育・解析特化型の簡略エニグマシミュレーター**である。

実機エニグマの忠実再現は目的とせず、以下を最優先とする。
- 問題文仕様との一致
- 内部状態の完全可視化
- 暗号化／復号の挙動を理解できること

---

## 2. 全体アーキテクチャ

- 種別: 静的Webアプリ
- 公開: GitHub Pages
- 構成:
  - `index.html` - UI構造
  - `style.css` - スタイル定義
  - `logic.js` - DOMに依存しない暗号処理と検証
  - `attack-core.js` - DOMに依存しない分割探索と候補集計
  - `comparison-core.js` - DOMに依存しないEnigma I教育サブセットと比較処理
  - `messages.js` - 日本語・英語の表示文言
  - `main.js` - UI、保存、初期位置探索、モデル比較
- 外部ライブラリ: 使用しない（Vanilla JS）

---

## 3. 対応文字集合

- 対象: A-Z（大文字英字のみ）
- 非英字（空白・数字・記号）:
  - 暗号処理対象外
  - 入力 → 出力へそのまま通過

---

## 4. 構成要素仕様

### 4.1 プラグボード（Plugboard）

#### 概要
入力・出力の両端で適用される文字置換機構。

#### 入力仕様
- 形式: テキスト
- 記法例: `A-B`, `A-B, S-Z, U-Y`
- 区切り: カンマまたは空白

#### 仕様ルール
- 指定されたペアは双方向置換
- 未指定文字は恒等写像
- 不正指定（同一文字ペアなど）は無視

---

### 4.2 スクランブラー（Scrambler / Rotor）

#### 枚数
- 1〜3枚（可変）
- OFFまたは空欄のスクランブラーは無効扱い

#### プリセット配線

| 名称 | 配線 |
|------|------|
| Enigma I | EKMFLGDQVZNTOWYHXUSPAIBRCJ |
| Enigma II | AJDKSIRUXBLHWTMCQGZNPYFVOE |
| Enigma III | BDFHJLCPRTXVZNYEIWGAKMUSQO |
| Enigma IV | ESOVPZJAYQUIRHXLNFTGKDCMWB |
| Enigma V | VZBRGITYUPSDNHLXAWMJQOFECK |

#### 各スクランブラーの属性
- 内部配線: A-Zを一度ずつ含む26文字文字列
- 開始位置: A-Zの1文字
- ノッチ位置: A-Zの1文字（デフォルト: Z）
- ノッチ有効/無効: ON/OFFトグル（デフォルト: ON）
- 元のID: 並び替えても維持される識別番号（1, 2, 3）

#### 回転仕様
- 毎文字処理前に最前段が必ず回転
- 前段スクランブラーがノッチ位置を超えると、次段が1回転（カスケード）
- ダブルステップなし（簡略化）

#### ノッチ機能
- 各スクランブラーに個別のノッチ位置を設定可能
- ノッチON/OFFトグルで有効/無効を切替可能
- ノッチON: 設定した位置を超えた時点で次段がカスケード回転
  - 暗号化時: 位置がノッチから次の文字に変化した時（例: C→D）
  - 復号時: 位置がノッチの次の文字からノッチに変化した時（例: D→C）
- ノッチOFF: 従来の26回回転でカスケード（位置Z→Aで発動）

#### ノッチの効果範囲
**重要**: ノッチは「そのスクランブラー自身」ではなく「次のスクランブラー」の回転タイミングを決定する。

| スクランブラー位置 | ノッチの効果 |
|-------------------|-------------|
| 1番目 | 2番目のスクランブラーがいつ回転するかを決定 |
| 2番目 | 3番目のスクランブラーがいつ回転するかを決定 |
| 3番目（最後） | 効果なし（後続のスクランブラーがないため） |

#### スクランブラーの並び替え
- ドラッグ&ドロップで視覚的な順序を変更可能
- 元のスクランブラー番号（ラベル）は維持される
- 例: Scrambler 2を先頭に移動しても「Scrambler 2」のまま表示
- 処理順序は視覚的な順序（左から右）に従う

#### 回転方向
- 暗号化・復号とも+1（左シフト）
- リフレクターなしの復号では、回転を逆にせず信号経路を末尾から逆配線でたどる

---

### 4.3 リフレクター（Reflector）

#### 概要
信号を折り返すための置換機構。

#### プリセット配線

| 名称 | 配線 |
|------|------|
| Reflector B | YRUHQSLDPXNGOKMIEBFZCWVJAT |
| Reflector C | FVPJIAOYEDRZXWGCTKUQSBNMHL |

#### 入力仕様
- 26文字の置換文字列
- A-Zを一度ずつ含むこと
- 自己逆写像であること
- 固定点を持たないこと
- 条件を満たさない場合は処理を中断し、理由を表示する

---

## 5. 暗号処理フロー（1文字）

### 5.1 リフレクターON

```
1. スクランブラー回転（処理前）
2. プラグボード（入力）
3. スクランブラー順方向通過（1 → 2 → 3）
4. リフレクター
5. スクランブラー逆方向通過（3 → 2 → 1）
6. プラグボード（出力）
7. 出力確定
```

同じ初期設定と同じ操作が自己逆変換になる。暗号化・復号のモード名は利用目的を示すが、処理経路は変えない。

### 5.2 リフレクターOFF（直通実験）

暗号化:

```text
回転 → プラグボード → スクランブラー順方向 → プラグボード → 出力
```

復号:

```text
回転 → プラグボード → スクランブラー逆順・逆配線 → プラグボード → 出力
```

直通実験は歴史的なエニグマ構成ではない。暗号化と復号の通過方向を明示的に分けるための教材である。

### アルゴリズム詳細

#### 順方向パス
1. 入力位置からシフト済みアルファベットの文字を取得
2. その文字を配線内で検索
3. 見つかった位置が出力位置

#### 逆方向パス
1. 入力位置から配線の文字を取得
2. その文字をシフト済みアルファベット内で検索
3. 見つかった位置が出力位置

---

## 6. 暗号化／復号モード

- UIで明示的に切替
- リフレクターON: モードにかかわらず同じ往復経路
- リフレクターOFF: 暗号化は順方向、復号は逆方向
- 回転はどちらも左方向で、同じ初期位置から各文字の処理前に進める

---

## 7. 入力バリデーション

### 配線バリデーション
- 26文字であること
- A-Zのみであること
- 重複がないこと
- リフレクターは自己逆写像かつ固定点なしであること

### 入力長
- メイン入力: 最大20,000文字
- 既知平文探索の暗号文: 最大200文字
- モデル比較入力: A-Zのみ、最大40文字

### エラー表示
- 入力欄の赤枠ハイライト
- エラーメッセージの表示
- 処理の中断

## 8. データ永続化

### localStorage
- キー: `cypher-enigma-settings`
- バージョン管理付き
- 自動保存（500msデバウンス）
- 表示言語は`cypher-enigma-language`へ独立して保存

### URLパラメータ

| パラメータ | 説明 |
|------------|------|
| `pb` | プラグボード設定 |
| `pbe` | プラグボード有効フラグ（0=OFF） |
| `s1`, `s2`, `s3` | スクランブラー配線 |
| `p1`, `p2`, `p3` | スクランブラー位置 |
| `n1`, `n2`, `n3` | スクランブラーノッチ位置（デフォルト以外のみ） |
| `ne1`, `ne2`, `ne3` | スクランブラーノッチ有効フラグ（0=OFF） |
| `e1`, `e2`, `e3` | スクランブラー有効フラグ（0=OFF） |
| `so` | スクランブラー順序（例: `231`、デフォルト以外のみ） |
| `rf` | リフレクター配線 |
| `rfe` | リフレクター有効フラグ（0=OFF） |
| `m` | モード（d=復号） |
| `lang` | 表示言語（en=英語、未指定=日本語） |

URLパラメータはlocalStorageより優先される。

## 9. セキュリティ対策

### HTTPヘッダー（meta タグ）
- **Content-Security-Policy**: スクリプト/スタイル/画像の読み込み元を`'self'`に制限
- **X-Content-Type-Options**: `nosniff`でMIMEタイプスニッフィングを防止
- **Referrer-Policy**: `strict-origin-when-cross-origin`でリファラー漏洩を防止

### 入力サニタイズ
- 配線: A-Zのみ許可、最大26文字
- 位置: A-Zのみ許可、最大1文字
- プラグボード: A-Z、ダッシュ、カンマ、スペースのみ、最大100文字
- URLパラメータ: 読み込み時に同様のサニタイズを適用
- メイン入力20,000文字、探索入力200文字の上限

### XSS対策
- 動的HTML生成時は`escapeHtml()`でエスケープ
- `textContent`/`value`で出力（可能な場合）
- `eval`/`Function`不使用
- 動的要素生成はハードコードされたプリセット配列から、または適切にエスケープ

### 外部リソース
- 外部ライブラリ不使用（依存関係なし）
- 外部リンクに`rel="noopener noreferrer"`を適用

### GitHub Pages固有
- `.nojekyll`ファイルでJekyll処理を無効化

## 10. 既知平文攻撃（解析支援）

### 10.1 概要

スクランブラーの配線はわかっているが、初期位置が不明な場合に、
暗号文と既知平文の一部から初期位置の候補を列挙する機能。候補は入力条件への一致を示すだけであり、正解や鍵全体の復元を証明しない。

### 10.2 前提条件

攻撃者が知っている情報:
- プラグボードの有無と設定
- スクランブラーの枚数と配線
- リフレクターの有無と設定
- 暗号文
- 暗号文の一部に対応する平文（既知平文）

### 10.3 探索アルゴリズム

```
1. 有効なスクランブラー数 n を取得
2. 26^n 通りの初期位置組み合わせを64通りずつ生成
3. 各バッチの間でブラウザーへ制御を返し、進捗表示とキャンセル操作を受け付ける
4. 各組み合わせについて:
   a. 設定オブジェクトを構築
   b. 復号モードで既知文字の最終位置まで処理
   c. 既知文字を入力位置の左から照合し、一致する接頭部分の長さを数える
   d. 各既知文字を追加した段階で残る候補数を集計
   e. すべて一致したら正確な一致件数を増やし、先頭100件だけを画面表示用に保持
5. 候補の詳細が開かれたときだけ全文の処理トレースを生成
```

### 10.4 探索空間

| スクランブラー枚数 | 組み合わせ数 |
|--------------------|--------------|
| 1枚 | 26通り |
| 2枚 | 676通り |
| 3枚 | 17,576通り |

### 10.5 主要関数

| 関数名 | 説明 |
|--------|------|
| `Attack.createSearchState(settings)` | 探索空間・候補数・絞り込み集計を初期化 |
| `Attack.advanceSearch(state, 64)` | 最大64通りを処理して進捗を返す |
| `Attack.getSearchSummary(state)` | 正確な一致件数・保持候補・絞り込み表を返す |
| `Attack.buildAttackSettings(positions, baseSettings)` | テスト用設定オブジェクトを構築 |
| `generatePlaintextGrid(ciphertext)` | 既知平文入力グリッドを生成 |
| `getKnownPlaintextFromGrid()` | グリッドから{position, char}ペアを収集 |

### 10.6 セキュリティ対策

- 暗号文入力はASCIIのみ許可（`beforeinput`イベントでフィルタ）
- 暗号文は最大200文字
- 動的HTML生成時は`escapeHtml()`でエスケープ
- 解析タブ専用の設定を使用（メインタブの設定を直接参照しない）
- 一致件数は全件を数えるが、DOMへ描画する候補は先頭100件に制限
- キャンセル時の候補数と絞り込み表は、確認済み範囲だけの途中結果と明示

## 11. モデル比較

### 11.1 目的と独立性

Cypher向け簡略モデルを変更せず、同じ入力・ローター・開始位置でEnigma I教育サブセットとの差を比較する。比較処理は`comparison-core.js`へ分離し、メインタブの設定、localStorage、URL共有には影響させない。

### 11.2 教育サブセット

- 左・中・右の3ローター。I〜Vから重複なく選択
- 反射板B/C
- 開始位置A〜Z
- リング設定A〜Z
- 打鍵前のローター回転
- 右ローターのノッチと中ローターのノッチによる連動
- 中ローターが連続する2打鍵で進むダブルステップ
- プラグボード、機種差、鍵配布、日鍵・通信鍵、通信運用は対象外

### 11.3 信号とリング設定

打鍵前に位置を進めた後、右→中→左の順方向、反射板、左→中→右の逆方向を通る。各ローターでは表示位置とリング設定の差を接点オフセットへ反映し、復路では逆配線を使う。

### 11.4 比較結果

- 両モデルの全文出力
- 出力が異なる文字数
- 選択リングでの教育モデル出力とリングAAA基準との差
- 各打鍵の入力、簡略モデルの処理後位置、教育モデルの処理前後位置
- ノッチまたはダブルステップを含む回転理由
- 両モデルの出力文字

### 11.5 既知ベクトル

- ローターI-II-III、反射板B、開始位置AAA、リングAAA: `AAAAA → BDZGO`
- 同条件で`HELLOWORLD → ILBDAAMTAZ`
- ローターI-II-III、開始位置ADU、リングAAA: 3打鍵で`ADV → AEW → BFX`

## 13. 日英表示

- 静的文言、入力補助、検証エラー、処理トレース、探索結果、モデル比較結果を日本語・英語で切り替える
- 言語切り替え時は既存の入力を保持し、出力・処理トレース・探索結果・モデル比較結果を選択言語で再描画する
- `html[lang]`、`document.title`、`aria-label`も同期する

## 14. テスト契約

- Cypher PUZZLE 01の既知ベクトル: `ZYDNI → ULTRA`
- リフレクター往復の自己逆性
- 直通実験の暗号化／復号の往復性と非恒等性
- カスタムリフレクターの自己逆性・固定点検査
- ノッチ境界とZ→Aカスケード
- 非英字の非変換・非ステップ
- 64通り単位の分割探索、途中進捗、候補保持上限
- 既知文字追加による候補数が単調非増加であること
- Enigma I教育サブセットの既知ベクトル、往復性、リング差
- ADUからの中ローターダブルステップ
- 比較タブ、サンプル、表、根拠資料のUI契約
- 日英キー、CSP、入力上限、モバイル1列契約

本設計は「問題が解けること」「動きが理解できること」を最優先とする。
